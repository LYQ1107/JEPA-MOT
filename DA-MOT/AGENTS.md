# Project execution rules

These rules apply to work in this DA-MOT workspace.

- Conserve tokens and do not continuously poll long-running jobs; inspect at
  milestones, completion boundaries, or errors.
- Normal correctness checks and experiment validation are allowed. Keep the
  work focused on the MOT/JEPA scientific question rather than turning it into
  a security exercise.
- Do not add large amounts of defensive code for basic, genuinely implausible
  cases.
- Treat rubrics as practical engineering guidance and document material
  trade-offs.
- Preserve useful failure evidence and provenance; do not overwrite failed
  experiment results or delete existing data without an explicit inventory.
- Prefer concise milestone reports over high-frequency status updates.
