# Registered comparison configurations

Run from the repository root with `./run_python.sh`. Paths below `runs/JEPA_CMOT` refer to local source checkpoints and source-only calibrations documented in `docs/JEPA_CMOT`. These copies preserve the actually launched configurations and replace only the machine-specific repository prefix with relative paths. Dataset images and large checkpoints are kept locally.

Frozen comparisons use `jepa_cmot.development_controls`; current object crops additionally select `--feature-name features_crop_current.npz`. Continual comparisons use `jepa_cmot.continual_controls`; H2 and competition controls pass the source `frozen_last.json` as `--teacher-calibration`. Use `--reverse` for the reversed target order and `--compact-intermediate` to keep full state at each domain boundary plus every intermediate model weight.

A matrix is final only after every native adaptation video and every frozen evaluation stage has completed. Multi-seed configs vary source-head initialization/sampling and online replay RNG while sharing the seed17 detector and fixed feature cache. The competition family uses the same native-group negative filter and nine memory fields across all four controls.

Pure-prediction continual configs separate cosine prediction from prediction+ranking. Reverse seed17 configs add these two controls to the existing six; UA forward seed23/42 and reverse all-seed configs share perception while preserving independent learners. Seed17 pure-prediction source heads use the original uniform source cache, so they can be compared with the original six-control sequence. These are registered pending experiments, not results.

`jepa_cmot.queued_sequences --plan LOCAL_PLAN.json` waits for complete experiment markers before using its assigned GPU, validates source files and unique control names, and launches whole native sequences plus matrix analysis. A local plan contains `gpu`, `dependencies` (complete marker, original PID and entrypoint), and `jobs` (dataset, controls, output, reverse). PIDs belong to this server session and must be updated when reproducing; they are not scientific parameters. `--validate-only` checks configuration files without launching training.

Paired official readouts are registered by `*_paired_{encoder,predictor}_w4_frozen.json`. Source checkpoints are pending until `jepa_cmot.paired_readout_pipeline` finishes source extraction/training/calibration. Run `CUDA_VISIBLE_DEVICES=2 ./run_python.sh -m jepa_cmot.paired_readout_pipeline --root runs/JEPA_CMOT/paired_readout_v1 --manifest runs/JEPA_CMOT/native_protocol_v3/manifest.json`; current scheduling additionally waits for the two existing UA feature-producer PIDs. Both source/development readouts use FP32 deterministic extraction, identical w4 causal pixels/ROIs, while the official predictor excludes the final tubelet's pixels and context tokens. Hidden sizes128/79 match trainable head capacity (662400/662657); the frozen predictor adds compute. Missing history is normalized zero. Startup/model loading and combined pair extraction time are explicitly separate from live inference FPS.

`*_frozen_prototypes.json` registers geometry, last, mean4 and lifetime EMA on the original dense-current readout. `jepa_cmot.calibrate_prototypes` fits only two source-validation sigmoid parameters per mean/EMA (200 steps), using the matching source cache and reference metrics. EMA beta=.25 is fixed; its physical-track state is reset per independent video and never updates the already frozen current query. `jepa_cmot.development_controls` deploys all native development videos with updates disabled.

`*_transformer_frozen.json` registers the source CE/prediction/joint transformer heads (662016 parameters, vs662400 for history MLP). `jepa_cmot.transformer_pipeline --dataset DATASET --root runs/JEPA_CMOT/transformer_v1` trains each for2000x64 on the same original source cache/seed17/gaps, calibrates on source only, then runs every native development video. No current candidate appears in the Transformer encoder; scoring follows the frozen history query. Source checkpoints for unfinished objectives remain pending.

`*_pair_MLP_frozen.json` uses `method=pair_scorer`: a frozen history-state encoder followed by a candidate-dependent scalar pair MLP (662229 parameters). `train_pair_scorer` uses the original matched source cache/reference split and 2000x64 CE updates, then fits only two source-validation sigmoid parameters for raw logits. It has no latent prediction loss. `pair_development_queue` launches every native development video after the actual source completion marker. Default tracker paths and learned JEPA objectives stay separate.
